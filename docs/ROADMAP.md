# Внутренний roadmap

Рабочий список для авторов. Главный README сюда не ссылается и этих пунктов не
упоминает: он описывает то, что инструмент делает сегодня. Состояние на
2026-11-19.

## Измерить на реальной модели

Приёмка с настоящим маленьким исполнителем не проводилась (пункт O4 в
[PROJECT_REVIEW_RESOLUTION_2026-10-01.md](PROJECT_REVIEW_RESOLUTION_2026-10-01.md)).
Весь путь проверен сквозными гейтами, но вместо модели в них работает сценарий
(`gate:dotnet`), поэтому неизвестно:

- какая доля делегирований заканчивается `verification_passed` и за сколько попыток;
- какая маленькая модель справляется лучше и сколько ей нужно памяти и времени на ответ;
- сколько ходов и токенов главной модели экономится на деле, отдельно для медленной
  локальной главной модели и для облачной.

Пока этого нет, README говорит об экономии как о том, откуда она берётся, без чисел.
Сценарий приёмки: [ACCEPTANCE_V0.md](ACCEPTANCE_V0.md). Для облачной главной модели
нужен ещё и сравнительный прогон без делегирования (пункт «frontier-model benchmark»
в обзоре 2026-10-01).

## Новые языки проверки

Сейчас проверка только для .NET. Следующие: Rust (`cargo build`, `cargo test`) и
Python (`pytest`). Для каждой экосистемы сначала нужно правило доказательства, что
тесты действительно выполнились, как TRX с `executed > 0` для .NET; иначе зелёный код
возврата будет врать. Это отдельная спецификация до кода (пункт F3 обзора 2026-10-01).

## Известные долги

- **Установка на Linux x64 и npm 12.** Скачивание CUDA-сборки `onnxruntime-node`
  отключено ключом в `.npmrc`. npm 11 предупреждает, что неизвестный ключ перестанет
  работать в следующей мажорной версии. К npm 12 нужен другой путь.
- **Лицензия.** В репозитории нет файла `LICENSE` и поля `license` в `package.json`.
- **Не проверено:** прогон коммитов запросов #28 и #29 на Windows; вызовы `dotnet`
  через `pi.exec` в живой сессии Pi; вызов `dotnet_build` и `dotnet_test` из Claude Code
  на Windows; macOS. Установка `pi install …@v0.2.0` на чистом Linux проверена.
- **Решения владельца:** дефект №7 (у результата провала preflight нет ключа `usage`);
  `"target": {"symbol": null}` превращается валидатором Pi в строку `"null"`; метрики
  `pi-lean-edit` под именем `line_edit` (O5); `pi-tree-sitter` рядом с `pi-lean-edit`
  (O6); список P2 обзора 2026-09-23 не перепроверен.
- **npm и установочные скрипты.** npm 11.16 предупреждает, что у 14 пакетов
  (`better-sqlite3`, `onnxruntime-node`, `protobufjs`, грамматики `tree-sitter`)
  установочные скрипты «not yet covered by allowScripts». Сейчас скрипты всё равно
  выполняются (проверено 2026-11-19: `better-sqlite3` собрался и работает). Если
  будущий npm начнёт блокировать их по умолчанию, у `pi-knowledge` не соберутся
  нативные модули.
- **Провайдер `claude-code`.** Не проверен на Windows: `claude.cmd` из npm не
  запускается без оболочки, а движок оболочку не использует. Синхронизированные с
  аккаунтом плагины CLI всё равно загружает (без `--bare`, который требует
  `ANTHROPIC_API_KEY`); в пробе их хуки не срабатывали. Задать температуру нельзя.
- **CI нет.** Гейты запускаются вручную перед слиянием.
- **Выпуск 0.3.1.** Версия поднята в `package.json`, `package-lock.json` и обоих
  манифестах `.claude-plugin`; тег `v0.3.1` ставится после слияния.
